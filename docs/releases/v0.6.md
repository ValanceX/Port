# PORT v0.6 release notes

## v0.6.1

*Released 2026-10-15 (`v0.6.1`).* A patch release; the two packages move together.

- **`@valancex/port-web`: events made by different keys may share a DOM event type.** `submit` on `keydown` Enter and `cancel` on `keydown` Escape are one text field's two events, and a table that says so is accepted. It was refused (found by wiring `cancel` for the web), though no key press can be both. A table is still refused when two events of a primitive share a type and the same key, or when either takes any key. A table accepted before resolves exactly as before.
- `@valancex/port-desktop-vocabulary` 0.6.1: no change.

## v0.6.0

*Released 2026-10-15 (`v0.6.0`).* A minor release of two packages that share one version and are published together: `@valancex/port-web` and the new `@valancex/port-desktop-vocabulary`.

### `@valancex/port-desktop-vocabulary` (new)

The Desktop PORT's vocabulary as data: `vocabulary.json` (the components a template may write for a native window, with their props and events) and `content.json` (the content layer). Until now a tool that checks templates, `vlx check` and the editors, carried a copy of these files and a test that the copy had not drifted. It reads them from this package instead (`@valancex/port-desktop-vocabulary/vocabulary.json`).

The crate `valancex-port-desktop` is still the source: the package's copies are made from its files before every pack and every test, and a test checks they are byte for byte the crate's. The crate itself stays unreleased, so the vocabulary is the **Unreleased** tier even though the package is published (see [API stability](../stability.md)): it may change before the crate's 0.1.

This release's vocabulary adds one event: `cancel` on a text field (Escape), beside `click`, `change` and `submit`. The window also gains the host message `navigate` (Alt+Left, Alt+Right and the mouse's back and forward buttons; unmapped on macOS). See "Keys" in the [architecture note](../architecture/2026-10-14-port-desktop.md).

### `@valancex/port-web` 0.6.0

No change to its API, behavior or peer range. It moves to 0.6.0 so the workspace has one version, and one tag publishes both packages.

### Release process

The release workflow now packs and publishes both packages from one `v0.6.0` tag, and refuses a release whose two versions differ. A partial publish (the first package accepted, the second refused) has to be finished by hand with `npm publish` of the tarball in the workflow's artifact.
