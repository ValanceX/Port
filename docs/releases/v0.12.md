# PORT v0.12 release notes

## v0.12.0

*Prepared 2026-10-23, not yet released.* A minor release of the two npm packages that share one version (`@valancex/port-web`, `@valancex/port-desktop-vocabulary`) and of the Desktop PORT crate (`valancex-port-desktop` 0.6.0, tag `desktop-v0.6.0`). It is the PORT's half of WP6b of the Valance direction work: layers.

### `@valancex/port-web` 0.12.0

- **`WebPrimitive.layer`, `layerProp`, `layerDismiss`.** A modal dialog (`<dialog>`, `showModal()`) and a popover (`popover` attribute, `showPopover()`), driven by the application's `open`. Server HTML writes a modal's `open`; hydration upgrades it. Escape and an outside press raise a `close` the application may refuse (the PORT reopens what the browser closed against `open`). Focus stays inside a modal: the platform lets Tab leave to the browser's own UI (measured), so the PORT wraps Tab and Shift+Tab (decision I20). Focus returns to the invoker by key; else to the layer's parent. A popover is placed at its anchor with CSS anchor positioning (`anchor-name`, `position-anchor`, `position-area`) where the browser has it. (Tier 3 for a table author; Tier 1 for an application: `open` is its state.)
- **Table checks** for layers: a table that is wrong is refused when it is created.
- **Evidence.** The Authoring Practices' modal dialog pattern is quoted in `overlays/apg-dialog-modal.source.json` (rows checked against the pinned page by `--check-source`) and generated into 33 vectors, all of which pass in Chromium; each is shown failing against a deliberate wrong behavior. A subset of the web-platform-tests (dialog and popover elements, focus) runs in Chromium at commit 30c8fa7; seven cases fail in the browser itself and are named in `integration/wpt/expected.json` with what each means.

Breaking? No. A table without `layer` is unchanged.

### `valancex-port-desktop` 0.6.0 and `@valancex/port-desktop-vocabulary` 0.12.0

- **`dialog`** (`open`, `label`) is egui 0.31's `Modal`: the backdrop blocks the pointer and focus is limited to the modal layer. The PORT adds initial focus, Tab and Shift+Tab wrap, Escape, and focus return to the invoker. Its node is a Dialog with `modal` set. **`popover`** (`open`, `anchor`, `placement`, `kind`) is an `Area` at the rect of the node whose `id` it names (`button` takes an optional `id`). The event verb **`dismiss`** is the eighth; the vocabulary has 22 components.
- **A radio group's radios are children of its node in the accessibility tree**, and **an inline link has an id made from its key** (decision I21), so a link keeps its accessibility node when its text changes.
- **`hovered` and `pressed`**: a themed `button` takes the theme's rules for them (the pointer over it, and held). `focus-visible` stays the toolkit's own ring.
- Tests read the tree with `accesskit_consumer`, the consumer the platform adapters are built on: the radio group's arrows and the modal's Tab wrap and focus return.
- Known differences: Desktop keys are checked against the Authoring Practices as the reference and read back through AccessKit's consumer, not through a platform screen reader; the real-window check was run under Xvfb.
