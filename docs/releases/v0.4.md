# PORT v0.4 release notes

## v0.4.0

*Prepared 2026-10-09 (not yet released: v0.3.0 is the latest release).* A minor release of `@valancex/port-web`. Before 1.0 a minor version is a new range; this one only adds.

### `patch(patches)`: apply an update in place

MESH 0.10's `update` and `updateChanges` return the new render **and** the `render-patch-v1` operations that turn the previous tree into it. `WebPort.patch(patches)` applies them to the DOM in place: `setProp`, `removeProp` and `setText` change a kept part; `insert`, `remove` and `move` add, take away and reorder parts among their siblings by key; `replace` swaps the whole tree. A part the patches do not name is not touched, so an element a user is typing in keeps its focus and selection, and the work is proportional to the change. The patches are validated against the drawn tree first and applied all or none; a refusal is a `WebRealizationError` with a `code` (`not-drawn`, `unsupported-patch`, `unknown-key`, `patch-failed`). A key index, kept by `draw`, `update`, `hydrate` and `unmount`, lets a patch find its target without walking the tree.

### `unmount` and `Symbol.dispose`

`unmount()` is safe to call twice and before any `draw`, and leaves the PORT usable: `draw` draws again, and `update` and `patch` refuse with `not-drawn`. Where the platform has `Symbol.dispose`, the Web PORT has `[Symbol.dispose]()`, the same as `unmount()`, so `using port = createWebPort(...)` works.

### `inspect` (not part of the contract)

`WebPort.inspect` and the touched keys `patch` returns are devtools hooks. They may change or go in any release.

### Compatibility

Additive. The peer range of `@valancex/mesh-runtime` is `^0.6.0 || ^0.7.0 || ^0.8.0 || ^0.9.0 || ^0.10.0`. See the [API stability](../stability.md) page for what each surface promises.

### Not changed

`attribute`, `booleanAttribute`, `controlled`, `property`, `textProperty`, event resolution, keyed update, hydration verification, server rendering.
