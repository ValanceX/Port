# PORT v0.3 release notes

## v0.3.0

*Released 2026-10-05 (`v0.3.0`).* A minor release of `@valancex/port-web`. Before 1.0 a minor version is a new range; this one only adds.

### `controlled(name)`: a field the user edits

A field the user edits had no correct realization. `attribute(name)` is the only form with an HTML form, and the DOM stops reading a `value` attribute once the user has typed in the field. `textProperty(name)` is live but cannot be server-rendered, and PORT diffed props against the **previous render**, not the DOM, so an application that reset, rewrote or declined an edit could leave the field showing text its state did not hold.

`controlled("value")` is the content attribute **and** the same-named DOM property:

- **Server and hydration are the attribute's.** It serializes as `value="…"`, hydration verifies that attribute, and the server's markup is adopted unchanged.
- **After every `draw`, `update` and `hydrate`, the DOM property equals the rendered text** (or the element's own initial value when the prop is absent), whatever the user did since and whether or not the rendered text changed. It is written only when it differs, so a field that agrees is untouched, and a **focused field keeps its selection** (clamped to the new length).
- **Nothing is written between presentations.** PORT cannot know whether the application accepted an edit, and writing the old value back at once would erase what the user is typing while the application decides. An edit the application declines by committing nothing therefore stays in the field **until the next presentation**, which reasserts the application's value. Text typed before `hydrate` is replaced by the rendered text.
- It applies where the attribute and the property share a name (`value`).

```ts
import { controlled } from "@valancex/port-web";
const primitives = { field: { element: "input", props: { value: controlled("value") }, events: { input: { type: "input", payload: (_e, el) => (el as HTMLInputElement).value } } } };
```

### Evidence

13 new tests (`packages/port-web/test/controlled.test.ts`): the server form, hydration (a matching server attribute is adopted; a different one is an ordinary attribute mismatch), a reset, a rewrite, a declined edit with and without a presentation, no redundant writes, selection preservation, and the property that still has no HTML form. Seven of them fail against plain `attribute`. The full suite is 272 tests. Confirmed end to end in real Chromium through `@valancex/valance`'s `Web.run`.

### Not changed

`attribute`, `textProperty`, `booleanAttribute`, `property`, event resolution, keyed update, hydration verification, server rendering.
