# PORT v0.11 release notes

## v0.11.0

*Prepared 2026-10-23, not yet released.* A minor release of the two npm packages that share one version (`@valancex/port-web`, `@valancex/port-desktop-vocabulary`) and of the Desktop PORT crate (`valancex-port-desktop` 0.5.0, tag `desktop-v0.5.0`). It is the PORT's half of WP6 of the Valance direction work: behavior (focus, groups, identity on the Desktop). It also carries what was unreleased before it: the window's theme and the button's `intent` and `size` (see the CHANGELOG).

### `@valancex/port-web` 0.11.0

- **Focus follows identity.** A browser drops focus from an element that is moved or removed. After `draw`, `update` and `patch` the PORT puts it back, by key, with a text field's selection and its direction; a part that is gone hands focus to what follows it, then what precedes it, then what holds it. The `focus` and `blur` of this restoring are not interactions and are not reported. (Tier 1: nothing to configure.)
- **`focus(key): boolean`.** The host's request, made after the patches that drew the part (Tier 2). It is a call on the PORT, not a command: focus is not application state. It focuses the part, or the first thing in it that takes focus.
- **`WebPrimitive.group: { within, attribute }`.** The DOM's own grouping. The element carries `attribute`, made from the key of its nearest ancestor drawn as `within`. Server HTML writes the key and hydration verifies it; in the browser the first port of a document keeps it and each later one makes it its own, so two groups, or two mounts of one tree in one document, never share a group. For a radio this is one tab stop and the arrow keys (Tier 3: a table entry for a primitive author).
- **`elementWhen(name)`.** A prop of kind `element` makes the primitive's element `name` while it is `true`. When it changes the PORT replaces the element: the new one takes the old one's children (each keeps its DOM node and state), the primitive's constants, group, props and place. Server HTML has the chosen tag; hydration verifies it (Tier 3).
- The peer range admits MESH 0.15, each line run.

Breaking? No. A table that does not use `group` or `elementWhen` is unchanged; `focus` is an added method.

### `valancex-port-desktop` 0.5.0

- **Widget ids come from node keys (I16).** egui seeds the automatic ids of a child `Ui` from its parent's counter, so `push_id` keeps `ui.id()` stable and not the ids of the widgets inside. Each component node is drawn in a `Ui` made by `Ui::new` from the parent's id and the node's key. All 19 identity vectors and the program steps keep a kept key's accessibility node (14 of 19 and four transitions did not). What egui remembers by id (a scroll position, an open section, a field's focus) follows the key.
- **Focus follows identity** and **`focus` over the host protocol** (additive; protocol 1; a window that does not know the message ignores it).
- **Roving focus in a radio group** (APG radio group keys, as the reference for keys only).
- Known differences: an inline link is not part of focus bookkeeping; Tab past the last widget wraps; the real-window checks were run under a virtual display (Xvfb, software GL) with real key presses, not on a physical display or another operating system.
