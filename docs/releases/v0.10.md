# PORT v0.10 release notes

## v0.10.0

*Prepared 2026-10-18, not yet released.* A minor release of the two npm packages that share one version and are published together: `@valancex/port-web` and `@valancex/port-desktop-vocabulary`. The Desktop PORT crate is released on its own tag (`desktop-v0.4.0`).

### `@valancex/port-desktop-vocabulary` 0.10.0

The Desktop PORT's vocabulary grows by three components, **additively**: a template written against 0.9 compiles and draws as before. The vocabulary is twenty components (and the nine of the content layer).

- **`status` and `alert`**, the live regions (decision A13 of the Valance direction work). The text inside is the message. `status` is polite and `alert` assertive, both atomic, as the ARIA roles imply. Neither has a name of its own.
- **`toggle`**, a button that stays pressed: `pressed` (required; the application owns it), `label` and `disabled` (optional); the event `change` carries the value the toggle is going to have, as a checkbox's does. Its content is its text. It replaces a web `button` carrying `pressed`.

With these the Valance primitives' parity report against this vocabulary needs no waiver.

### `@valancex/port-web` 0.10.0

**The peer range admits `@valancex/mesh-runtime` 0.13 and 0.14**: `^0.6.0 || ... || ^0.12.0 || ^0.13.0 || ^0.14.0`. The range is no longer only listed: `scripts/check-mesh-range.mjs` installs each line and runs the suite against it (`pnpm exec node scripts/check-mesh-range.mjs`, and CI's `mesh-range` job). All nine lines pass, 0.6 to 0.14. The program vectors (MESH 0.14's `enums/`, `snippets/`, `forwarder/`, `passing/`) are run against 0.14 only, because they use its constructs. No change to the API or behavior.

### The Desktop PORT crate, 0.4.0

`valancex-port-desktop` 0.4.0 draws the three components. `status` and `alert` set the Status and Alert roles and their live settings, which egui never emits, and exist as nodes before they have text (the APG alert pattern). `toggle` is a Button whose pressed state is the accessibility tree's toggled state; a click, or Enter or Space when it has focus, reports `change` with the new value. The 0.3.1 fix for table cells is included. Headless tests read the accessibility tree back; a real window was not driven for the new components.

### What this release does not do

- The arrow keys among radios are the browser's on the web (they move focus and select, as the pattern says, but the radios are not one group to the browser, so Tab visits each) and are not handled on the Desktop. A group's radios sharing a name on the web, and roving focus on the Desktop, are the Valance direction's WP6.
