# PORT v0.2 release notes

## v0.2.2

*Released 2026-10-02.* A patch release: **`@valancex/port-web`'s API is unchanged**, and `update` now matches children by key, as the contract has always said. The [changelog](../../CHANGELOG.md) has the details.

- **`update` keeps one DOM node per key.** Through 0.2.1 it compared children by position and only checked the key there, so a key at a new position was replaced, along with everything after it. That was invisible while every tree of a program had the same structure, and wrong as soon as it didn't: MESH 0.7's conditional and repeated structure inserts, removes and reorders children. Now a key in both trees keeps its node (moved only if out of place), a new key gets a node, a removed key has its node disposed, and a key that leaves and returns gets a fresh node. This is recursive. Handlers stay with their key.
- **A key whose component changes is replaced.** A target realization is retained only when the key and the component are compatible ([CONTRACT.md](../CONTRACT.md)). This is PORT's own rule for a node that cannot become a different component, not a statement about MESH identity.
- **A duplicate key** was already refused before anything is drawn, and still is.
- **`@valancex/mesh-runtime` peer range** is `^0.6.0 || ^0.7.0`: `^0.6.0` excluded MESH 0.7. PORT still imports only MESH's types, and treats a key as opaque.
- **Evidence:** keyed reconciliation is tested at PORT's boundary with hand-written render-v1 trees, and in the integration workspace with real MESH conditional and repeated output.
- **Not changed:** hydration (and it is not tested with dynamic structure), server rendering, value realization and event resolution.

## v0.2.1

*Released 2026-09-28.* A patch release: **`@valancex/port-web` is unchanged** from 0.2.0 in source, API and behavior. The release adds evidence and tidies the private integration workspace. The [changelog](../../CHANGELOG.md#021---2026-09-28) has the details.

- **A Chromium tracer bullet** (`integration/browser/`, in CI).
  - **The composition:** MPRX → the MESH compiler (Node) → `@valancex/mesh-runtime` (WebAssembly, `init` in the page) → a NEXUS application whose `users.refresh` requires one capability → a test-local platform (the capability, and Clock 42) → the composer → `@valancex/port-web` → Chromium, with real clicks.
  - **What passes:** MESH's reviewed intent, capability resolution, and the same `<img>` updated in place.
  - **Caller isolation:** application code sees the platform's Clock, and the caller never does, even though it gets its results with `Fiber.join`.
  - **The negative path:** an absent capability is incompatible, the application still starts, only Refresh fails (`CapabilityUnavailableError`), and nothing else changes.
  - **What it needed:** no ownership change. PORT still doesn't depend on NEXUS, and rendering stays with the composer.
- **NEXUS 0.9 in the integration workspace** (`@valancex/nexus` `^0.9.0`). The temporary `pnpm.overrides` entry for NEXUS's MESH runtime range is removed. There is still one `effect` and one `@valancex/mesh-runtime`.

## v0.2.0

*Released 2026-09-28.*

v0.2 makes the Web PORT a complete realization of MESH v0.6's render trees. It realizes values and events exactly as MESH specifies. It also renders the same trees on a server, as HTML, and hydrates that HTML in the browser, for a deliberately narrow subset, with no second value system and no new metadata. render-v1, MESH and NEXUS are unchanged. The [changelog](../../CHANGELOG.md) has the full list.

## Highlights

- **MESH v0.6 realization.** Each prop goes to a slot the application's realization table names, and is realized there in one of MESH's two ways (§9.8.7):
  - **natively:** `property`, or `booleanAttribute`, which takes only a boolean, realized by presence;
  - **as MESH's text:** `attribute` or `textProperty`, taking a string's own value or the runtime's `propText`.

  A value that fits neither is refused. PORT makes no text of a value, and a DOM property and an HTML attribute never stand in for each other.
- **MESH event resolution** (§9.9). One interaction reaches at most one binding, the innermost qualifying one. The DOM's bubbling decides nothing.
- **Server rendering.** `realizeHtml(tree, primitives)`, from `@valancex/port-web/server`, uses no DOM. It shares the client's validation and value realization, writes deterministic HTML with parse-verified escaping, and returns complete HTML or throws. It writes no keys, handler identifiers or program identity. Parsing and hydrating its HTML gives exactly what a fresh client `draw` gives.
- **Hydration.** `WebPort.hydrate(tree)` pairs the client's own tree with the server DOM by position.
  - A tree is fully verified before adoption begins, and structural verification is mutation-free.
  - A match is adopted with every server node kept, and `update` follows as after a draw.
  - Any structural mismatch means a complete fresh draw, with the first mismatch reported.
  - Adoption is not transactionally rollbackable across arbitrary DOM property setters: a setter that throws makes `hydrate` throw `adoption-failed`, with no retry and no fallback draw.
  - `hydrate` is Web-specific, not a PORT contract operation.
- **Through NEXUS.** The integration slice runs NEXUS state → MESH → `realizeHtml` → a parsed page → a client NEXUS with the same state → `hydrate` → click → NEXUS → `update` of the server's own nodes. PORT doesn't depend on NEXUS; the composer connects them.

## Not included

Streaming; progressive or partial hydration; islands; event replay; routing; server components; preserving pre-hydration input; deferred property serialization; mismatch patching; parser recovery; SVG and MathML; other targets.

## Known limitations

These are v0.2's documented semantics:
- **Structural mismatch:** a fresh draw, so the server-rendered DOM isn't reused.
- **Parser restructuring:** nestings the HTML parser rewrites are caught only at hydration, as a mismatch.
- **Adoption setter failure:** `adoption-failed`, with no rollback.
- **Pre-hydration input:** lost in slots the client's tree realizes as present properties.
- **Pre-hydration interactions:** lost; nothing is replayed.
- **Several DOM event types from one gesture:** several interactions, when a realization table maps them.

## Compatibility

- **MESH v0.6:** `@valancex/mesh-runtime` `^0.6.0` is the only peer dependency, used for the render tree's types.
- **NEXUS 0.8.0:** integration-tested through the composer.
- **Temporary override:** the repository's test workspace overrides NEXUS's `@valancex/mesh-runtime` range to `^0.6.0`, solely because NEXUS 0.8.0 declares `^0.5.0`. It doesn't affect `@valancex/port-web`, and will be removed in a separate change once NEXUS releases a version accepting MESH 0.6.

## Upgrading from the pre-v0.2 Web PORT

- **Realization tables:**
  - A number, boolean or `null` in `attribute` now takes MESH's `propText` rather than being refused.
  - `property` and `textProperty` are new.
  - Tables are validated when the PORT is created (`invalid-primitives`): one realization per source prop, unique attribute and property names, lowercase element and attribute names, and one event per DOM event type per primitive.
- **Events:** a click on a bound node inside another bound node reports the inner binding only. Before v0.2 the DOM's bubbling reported both.
- **Payload builders** receive the receiving node's element as a second argument.
