# PORT v0.14 release notes

## v0.14.0

*Prepared 2026-10-24, not yet released.* A minor release of the two npm packages that share one version (`@valancex/port-web`, `@valancex/port-desktop-vocabulary`). The Desktop PORT crate is unchanged (`valancex-port-desktop` 0.6.0).

### `@valancex/port-web` 0.14.0

- **The MESH runtime peer range admits 0.17.0** (`^0.6.0 || … || ^0.16.0 || ^0.17.0`). v0.13.0's range stops at 0.16, so once MESH 0.17 is published `npm` would refuse `@valancex/mesh-runtime@0.17.0` beside `@valancex/port-web@0.13.0` and the newest set would not install together (Valance's budgets check it at every release, Bet 3). MESH 0.17 adds checking a source while it arrives and the `effect` and `title` of a command in the manifest; it changes nothing the PORT draws, and the PORT is unchanged.
- **The line was run, not only listed.** `scripts/check-mesh-range.mjs 0.17.0=<conformance>` (with `MESH_PACK_DIR` naming the packs until 0.17.0 is published: the script then installs from them) ran the Web PORT's suite with MESH 0.17.0's compiler and runtime and the 0.17 conformance package as the vector set: 26 files, 435 tests pass. `test/architecture.test.ts` pins the lines the range names (6 through 17) and fails if one is added without a run.

### `@valancex/port-desktop-vocabulary` 0.14.0

Version only (the two packages share one). No change.

Breaking? No. **Tier:** not a public-API change; no audit of the north-star scorecard is touched.

### Release steps (the maintainer's)

1. Merge when CI is green, after MESH 0.17.0 is published. 2. Tag `v0.14.0` (npm, `release.yml`). The crate is not released. 3. In Valance, raise `@valancex/port-web` and `@valancex/port-desktop-vocabulary` to `^0.14.0`.

### Verification

`pnpm build`, `pnpm typecheck`, `pnpm test` (port-web 435, the vocabulary package, the integration suite 28), `MESH_PACK_DIR=<packs> node scripts/check-mesh-range.mjs 0.17.0=<conformance>`, `node scripts/check-conformance.mjs`; installs under pnpm 10 and 11 with `--frozen-lockfile`; `npm publish --dry-run` for both packages.
