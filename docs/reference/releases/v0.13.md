# PORT v0.13 release notes

## v0.13.0

*Prepared 2026-10-24, not yet released.* A minor release of the two npm packages that share one version (`@valancex/port-web`, `@valancex/port-desktop-vocabulary`). The Desktop PORT crate is unchanged (`valancex-port-desktop` 0.6.0).

### `@valancex/port-web` 0.13.0

- **The MESH runtime peer range admits 0.16.0** (`^0.6.0 || … || ^0.15.0 || ^0.16.0`). v0.12.0's range stopped at 0.15 and MESH 0.16 is published, so `npm` refused `@valancex/mesh-runtime@0.16.0` beside `@valancex/port-web@0.12.0` and the newest published set did not install together (Valance's budgets check it at every release, Bet 3). MESH 0.16 adds no runtime or compiler behavior (its release is the session-log vectors in `@valancex/mesh-conformance`), and the PORT is unchanged.
- **The line was run, not only listed.** `scripts/check-mesh-range.mjs 0.16.0` installs MESH 0.16.0's compiler and runtime into a scratch directory and runs the Web PORT's suite with them: 26 files, 435 tests pass, with the 0.16 conformance package as the vector set. `test/architecture.test.ts` pins the lines the range names (6 through 16) and fails if one is added without a run.

### `@valancex/port-desktop-vocabulary` 0.13.0

Version only (the two packages share one). No change.

Breaking? No. **Tier:** not a public-API change; no audit of the north-star scorecard is touched.

### Release steps (the maintainer's)

1. Merge when CI is green. 2. Tag `v0.13.0` (npm, `release.yml`). The crate is not released. 3. In Valance, raise `@valancex/port-web` and `@valancex/port-desktop-vocabulary` to `^0.13.0`.

### Verification

`pnpm build`, `pnpm typecheck`, `pnpm test` (port-web 435 and the integration suite), `node scripts/check-mesh-range.mjs 0.16.0`, `node scripts/check-conformance.mjs`; installs under pnpm 10 and 11 with `--frozen-lockfile`; `npm publish --dry-run` for both packages.
